## Guide

Header is a primitive: it owns how the outer wrapper behaves on scroll, and nothing inside it. It is static by default.

**Position.** `position="sticky"` keeps it in the flow and sticks it at `offset` (the `header.offset` token by default) inside its containing block; when that block ends, the header is pushed out and its state becomes `released`. Prefer sticky. `position="fixed"` pins it to the viewport and leaves a placeholder of its measured height in the flow, for layouts where sticky cannot work (an ancestor with `overflow`, or a short parent). Fixed stays in the flow until it mounts, so a page without script, or before hydration, shows it above the content and nothing shifts; it also stays in the flow while the on-screen keyboard is open. Inside a `root` scroll container, fixed renders sticky.

**Height.** While sticky or fixed, Header writes its measured height to `--np--header--height` and its height plus offset to `--np--header--inset` on the root (the page's `html`, or the `root` container), read with `getToken("header.height")` and `getToken("header.inset")`. With several headers on one root, the tallest wins. A zero-specificity rule, `:where([data-np-header-root]) { scroll-padding-top: var(--np--header--inset) }`, makes in-page links and `scrollIntoView` land below it; a `scroll-padding-top` of your own overrides it. A header whose stuck appearance is a different size keeps the flow height of its default appearance, and the variables wait for the size transition to end, so the page is not restyled every frame.

**Safe area.** With `viewport-fit=cover`, a header stuck at the top edge (offset 0), or fixed there, pads its top by `safe-area-inset-top`; a header resting mid-page does not. A fixed header pads its physical left and right by the side insets; a sticky one does not, because the reset already pads the body's sides. The inset tokens are `header.safeArea.top`, `.left` and `.right`.

**States.** `data-state` is `static`, `stuck`, `hidden` or `released`, reported through `onStateChange` and forced with `state`. Stuck is detected by an IntersectionObserver on a marker at the point where the header sticks, so there is no scroll listener and the top rubber-band never reads as stuck; `threshold` moves that point down, so the header first scrolls away and then slides back in. `hideOnScroll` hides it on scroll down and reveals it on scroll up, after `tolerance` pixels in one direction. Overscroll is ignored. It is revealed at the end of the content and by focus inside it. In-page links, hashchanges and focus-driven scrolls pause it until `scrollend`, and the open on-screen keyboard pauses it and shows the header. Change `resetKey` on a route change to show the header and restart. `stopAt` (a scroll distance, or an element whose bottom edge pushes it out) releases it. `hideOnScroll` and `stopAt` share one passive scroll listener, batched to one update per frame, attached only when either is set.

**Appearance.** `appearance.default` and `appearance.stuck` set the background, text, border and shadow colours and the font size from core tokens; unset values take the `header.*` tokens. The stuck background is opaque: do not add `backdrop-filter` to a sticky header, which WebKit renders incorrectly (bug 298709). The change between states takes `transitionDuration` and `transitionEasing` (the `header.transitionDuration` and `header.transitionEasing` tokens by default) and is instant under `prefers-reduced-motion`. Every prop also takes per-breakpoint values through `breakpoints`, for example `breakpoints={{ "tablet-": { position: "static" } }}`.

## Building on Header

Context-specific headers (a page header with a title, navigation and actions) are built on Header: they render their layout as Header's children and pass the scroll behaviour through, so every one of them sticks, hides, stops and measures the same way. Style their content per state from `data-state` on the `header` element, or from `onStateChange`.
